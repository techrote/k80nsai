## Recommendation and evidence limits

Recommend **ggml-org/llama.cpp**, branch context **master**, exact revision **56381e407c0ccfb3a6f71e668a27a901001d22ce** (M), over **PrismML-Eng/llama.cpp**, branch context **prism**, exact revision **d8f26eec76da6d09bb708bcba51ef64b8cd868a3** (P). M already contains the native binary Q1 format, CUDA Q1 vector dot, Qwen3 small-model graph and Qwen35 hybrid text graph. Most inspected P additions serve other hardware, ternary formats, optional speculation or launch optimizations. M additionally contains a **GDN Q/K normalization correctness change absent from P**; this is a substantive advantage, not branding or recency.

This is a reproducible engineering base recommendation, **not certification that either pin builds or runs on K80**. The same unresolved CUDA 11/sm_37 compilation, BF16 compute selection, cuBLAS batch calls and real-model shape/memory gates remain. There is no demonstrated Prism-only binary-text requirement in the inspected source. Exact Q1 GGUF headers/tensor inventories and numerical behavior remain K06/K07 gates; an unexpected private tensor type or unsupported graph requirement must reopen the source decision rather than silently select another model.

## Correctness difference: Qwen35 GDN normalization is not merely fused launches

**S:** M Qwen35 [qwen35.cpp:427–430](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/qwen35.cpp#L427-L430) calls `build_gdn_l2_norm` separately for Q and K. [models.h:13–18](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/models.h#L13-L18) implements `ggml_scale(ggml_rms_norm(x, eps/n), 1/sqrt(n))`. Algebraically this is `x / sqrt(sum(x*x) + eps)` (apart from floating-point evaluation order).

**S:** P [qwen35.cpp:490–505](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/qwen35.cpp#L490-L505) joins the Q/K head views then calls `ggml_l2_norm`. Its [CUDA norm.cu:297–330](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/norm.cu#L297-L330), especially line 326, computes `rsqrt(max(sum(x*x), eps*eps))`, i.e. `x / max(norm(x), eps)`. The unchanged generic L2 operator in M has the same max semantics; the difference is which model operation is built.

**P:** The source explicitly references [upstream PR #28068](https://github.com/ggml-org/llama.cpp/pull/28068), merged 2026-09-06, whose stated purpose is to match reference GDN epsilon placement. The discussion acknowledges potentially small numerical impact; its measurements are other-model third-party evidence, not Bonsai/K80 measurements. Do not quote them as ours.

**I:** Classify this as **compatibility/correctness relevant**, not merely optional optimization. Retain M's existing graph behavior in K04/K08; do not import P's merged normalization as a harmless optimization. A future deliberate port needs a small numerical fixture that distinguishes the formulas, including very small nonzero vectors, and a preserved reference baseline. This changes the earlier informal characterization of the P Q/K difference as launch-count-only. Neither source inspection nor the upstream PR proves exact Bonsai-27B quality.
