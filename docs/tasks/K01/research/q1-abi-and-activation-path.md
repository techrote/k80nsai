## 1. Native Q1 representation

**Fact:** Both snapshots declare `QK1_0=128`, `block_q1_0 { ggml_half d; uint8_t qs[QK1_0/8]; }`, and assert `sizeof(block_q1_0)==sizeof(ggml_half)+QK1_0/8`. Host `ggml_half` is a 16-bit storage type, CUDA uses `half`. Consequently the declared native block is 18 bytes, with 16 sign bytes and a single FP16 group scale. This is not a float scale plus four aligned words. [M common.h L1–29](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-common.h#L1-L29), [M block L180–185](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-common.h#L180-L185), [P block L185–190](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-common.h#L185-L190).

**Fact:** `quantize_row_q1_0_ref` computes `sum(abs(x))/128`, converts that scale to FP16, zeros the bit array, and sets bit `j%8` of byte `j/8` when `x[j]>=0`. CPU `dequantize_row_q1_0` reads the stored FP16 scale and returns that scale for bit 1 or its negation for bit 0. This establishes least-significant-bit-first element order within each byte. Native decode does not recompute the scale or take its absolute value. Although the normal reference encoder produces nonnegative scales, a stored negative finite scale must be preserved by a decoder/oracle. [M encoder L40–72](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-quants.c#L40-L72), [M decode L419–437](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-quants.c#L419-L437), [P encoder L40–72](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-quants.c#L40-L72), [P decode L454–472](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-quants.c#L454-L472).

**Inference:** In a naturally aligned contiguous array, group `g` begins at byte `18*g`, signs at `18*g+2`. For a base aligned to 4 bytes, the signs therefore alternate between addresses 2 and 0 modulo 4. A cast of every Q1 sign-array address to a naturally aligned `uint32_t*` is invalid. The existing CUDA Q1 dot uses `int16_t*` for the sign bytes, consistent with their two-byte alignment. The source's generic helpers explicitly distinguish `get_int_b1` (byte assembly), `get_int_b2` (assumes two-byte alignment), and `get_int_b4` (assumes four-byte alignment). The `get_int_b4` calls in Q1 dot operate on Q8 sign bytes, not the 18-byte Q1 blocks. [M helpers L7–29](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/vecdotq.cuh#L7-L29), [M Q1 loads L681–701](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/vecdotq.cuh#L681-L701).

**Fact:** `ggml_row_size(type,ne)` asserts divisibility by block size and returns `type_size*ne/block_size`; ordinary tensor construction sets `nb[0]=type_size`, `nb[1]=nb[0]*(ne[0]/block_size)`, and outer strides recursively. For Q1, an ordinary row is `18*(K/128)` bytes. [M row size L1333–1344](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml.c#L1333-L1344), [M ordinary strides L1833–1837](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml.c#L1833-L1837).

**Fact:** MMVQ asserts `nb00==ggml_type_size(src0->type)`, `nb10==sizeof(float)`, `dst->nb[0]==sizeof(float)` and propagates outer strides. Weight strides are divided by native block byte size; source activation strides are divided by F32 byte size. The Q8 temporary is contiguous in its own padded layout. Thus its stride must not replace the original F32 input stride in a basis encoder. [M mmvq.cu L1405–1429](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmvq.cu#L1405-L1429), [M strides L1484–1519](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmvq.cu#L1484-L1519), [P corresponding L1359–1383](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/mmvq.cu#L1359-L1383), [P strides L1436–1471](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/mmvq.cu#L1436-L1471).

**Proposal for K05/K08:** Use byte-addressed rows/views and safe bit extraction initially. Test adjacent blocks and an odd number of blocks per row, outer row strides that exceed packed row size, and unsupported stride rejection. Do not infer support for arbitrary byte strides merely from a stride parameter: the existing MMVQ conversion to block units assumes exact divisibility. Validate divisibility and bounds explicitly before admitting custom kernels. No synthetic native tail padding is authorized; require complete g128 groups or reference fallback.

## 2. F32 activation → Q8_1 reference → F32 output

The concrete unfused CUDA MMVQ path is the same in both pins:

1. **Fact:** `ggml_cuda_mul_mat_vec_q` receives full `src0`, `src1`, optional expert IDs, destination, and optional fusion arguments. It asserts F32 activation/destination, obtains `src1_d=(const float*)src1->data`, `dst_d=(float*)dst->data`, and uses `ctx.stream()`.
2. **Fact:** It computes `ne10_padded=GGML_PAD(ne10,MATRIX_ROW_PADDING)`, acquires `ggml_cuda_pool_alloc<char>` for Q8_1, then invokes `quantize_row_q8_1_cuda` with original F32 pointer and original outer strides. M conversion call is L1490; P is L1442. Existing compute-buffer padding handling is M L1473–1482/P L1425–1434 and must not be blindly copied onto views.
3. **Fact:** `quantize_q8_1` reads `x[i03*s03+i02*s02+i01*s01+i00]`; padded lanes read zero. Per 32 values it reduces absolute maximum and sum, computes `d=amax/127`, and stores `q=0` for an all-zero block or `roundf(xi/d)` otherwise. It writes `ds=make_half2(d,sum)`. Thus the emitted low half is rounded FP16 scale. Note the implementation stores the original F32 sum rounded to FP16 in the high half; the struct comment calls it `d*sum(qs)`. For Q1 this distinction does not affect the dot because it uses only the low half. [M quantizer L54–101](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/quantize.cu#L54-L101), [M launch L558–573](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/quantize.cu#L558-L573), [M Q8_1 struct L258–269](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-common.h#L258-L269), [P quantizer L55–102](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/quantize.cu#L55-L102), [P launch L638–653](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/quantize.cu#L638-L653).
4. **Fact:** `vec_dot_q1_0_q8_1` processes one of four 32-element chunks (`iqs`) within a 128-element native Q1 block. The weight has one scale shared over all four chunks; each Q8_1 chunk has its own scale. It expands Q1 bits to signed ±1 bytes, performs eight four-byte dot contributions over each selected 32-element chunk, then returns float `d1*d8*sumi`. Q1 does not consume `Q8_1.s`. [M full dot L678–726](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/vecdotq.cuh#L678-L726), [P full dot L707–762](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/vecdotq.cuh#L707-L762).
5. **Fact:** MMVQ accumulates thread partials into `float tmp`, reduces in shared float storage and warp sums, and writes float output. When fusion is active, float biases/gates/GLU arithmetic precede the store. [M mmvq.cu L692–818](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmvq.cu#L692-L818). P corresponding anchors are float temporary L664, reduction L801, store L837; the surrounding kernel includes an additional fast path, so do not transplant M line ranges mechanically.

**Inference:** Calling the CUDA Q1 path “the F32 reference dot” without qualification would be misleading: the graph boundary is F32, but MMVQ internally quantizes original activations to Q8_1. A basis implementation should encode the original activation before this conversion, and compare numerical errors against an independent decoded-weight/F32-activation oracle as well as runtime reference outputs.

**Fact:** Host runtime reference is a different path: Q1 CPU traits select `ggml_vec_dot_q1_0_q8_0` and `GGML_TYPE_Q8_0`, not Q8_1. The scalar generic dot explicitly decodes Q1 sign bytes, uses four Q8_0 blocks per Q1 group and their individual scales, then accumulates floats. [M CPU traits L228–233](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cpu/ggml-cpu.c#L228-L233), [M generic dot L127–176](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cpu/quants.c#L127-L176). K05 must not mistake “host reference” for an independent exact F32 oracle.

## 3. cc370 dispatch and fallback conclusions

**Fact:** Ordinary `ggml_cuda_mul_mat` checks unsafe padding-clearing views or non-F32 source1/destination first and calls cuBLAS in those cases. It then tries MMVF, transposed MMVF, MMF, MMVQ, MMQ, and finally cuBLAS. MMVF's switch admits floating types and defaults false; MMF rejects quantized types. [M dispatch L1815–1869](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/ggml-cuda.cu#L1815-L1869), [M MMVF L809–874](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmvf.cu#L809-L874), [M MMF L133–137](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmf.cu#L133-L137).

**Fact:** For ordinary Q1 at cc370, `ggml_cuda_should_use_mmvq` has no minimum architecture rejection; its generic return is `ne11<=MMVQ_MAX_BATCH_SIZE`, with the constant equal to 8. [M predicate L318–412](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmvq.cu#L318-L412), [M max batch L1–3](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmvq.cuh#L1-L3), [P predicate L293–382](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/mmvq.cu#L293-L382).

**Fact:** MMQ recognizes Q1 but requires architecture conditions it cannot satisfy at cc370. In M, if highest compiled compatible architecture is below DP4A, it returns `cc>=600 && n_experts>0`; P simply returns false below DP4A. Both reject ordinary Q1 MMQ at cc370, including when `GGML_CUDA_FORCE_MMQ` is defined because that override follows the rejection. [M MMQ L266–334](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/mmq.cu#L266-L334), [P MMQ L366–451](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/mmq.cu#L366-L451).

**Inference, source-level branch result only:** With a working cc370 build, eligible ordinary Q1×F32 operations with 1–8 columns reach MMVQ; larger-column Q1 operations reach cuBLAS after the MMQ predicate rejects them. Unsafe padding views/non-F32 boundaries reach cuBLAS earlier. This is not execution evidence or a guarantee that the entire unmodified source can compile for sm37.

**Fact:** For quantized src0, cuBLAS chooses F16 only when `fast_fp16_hardware_available(cc)` is true, otherwise F32. The hardware predicate excludes cc370. Absent explicit compute-type environment overrides, cc370 therefore selects F32; weights are converted into pool allocations before cuBLAS, with contiguous and noncontiguous Q1-to-F32 conversions available. [M selection L1622–1662](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/ggml-cuda.cu#L1622-L1662), [M hardware predicate L320–323](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/common.cuh#L320-L323), [M conversion allocation L1424–1470](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/ggml-cuda.cu#L1424-L1470), [M F32 converter L575–578](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/convert.cu#L575-L578), [M noncontiguous converter L682–687](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/convert.cu#L682-L687). **Inference:** Larger prefill fallback can carry a substantial temporary-memory cost from dequantized weights. Size and peak memory require actual model shapes and execution; they cannot be inferred solely from GGUF byte size.

**Fact:** `GGML_CUDA_CC_DP4A=610`. `ggml_cuda_dp4a` uses native `__dp4a` only at/above that architecture (or MUSA). Below it, the source casts each operand to four signed int8 values and adds their four scalar products to `c`. [M threshold L48–52](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/common.cuh#L48-L52), [M helper L714–752](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/common.cuh#L714-L752), [P helper L704–742](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/common.cuh#L704-L742). **Inference:** Q1 MMVQ does not intrinsically require native DP4A. This says nothing about other modern intrinsics, half helpers, launch machinery, toolkit compatibility, or full-model operators. K04 must compile the selected source and inspect/run the target route.

## 4. Fusion differences and safe interception scope

**Fact:** Both `ggml_cuda_should_fuse_mul_mat_vec_q` predicates immediately reject `cc<=600`; cc370 therefore does not use the ordinary Q1 MMVQ gate/up/bias fusion controlled by this predicate. For newer devices, both require one ordinary MUL_MAT output column. M admits MUL_MAT_ID fusion up to an architecture/type-specific bound; P requires `dst->ne[2]==1`. [M fusion predicate L1786–1812](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/ggml/src/ggml-cuda/ggml-cuda.cu#L1786-L1812), [P fusion predicate L1787–1813](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/ggml-cuda.cu#L1787-L1813).

**Fact:** Prism adds a Q1/PQ2 Hopper path at `ne11>=128`, behind `ggml_cuda_should_use_mmq`; it cannot be reached for Q1 at cc370 because that predicate is false. [P dispatch L1863–1877](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/ggml-cuda.cu#L1863-L1877).

**Fact:** Prism also has GB10-specific GLU-plus-quantizer fusion, dual-normalization/MMQ reuse, virtual normalized activations, and shared-Q8 projection reuse. These are explicitly gated to `cc==GGML_CUDA_CC_DGX_SPARK`, often multi-column prefill, and hence do not apply to cc370. They matter when choosing a general interception seam because not all runtime graphs necessarily materialize the “original” normalized F32 activation on all devices. [P GLU/dual path L3298–3356](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/ggml-cuda.cu#L3298-L3356), [P virtual RMS gate L4326–4350](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/ggml-cuda.cu#L4326-L4350), [P shared Q8 L4397–4429](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/ggml/src/ggml-cuda/ggml-cuda.cu#L4397-L4429).

**Proposal for K08:** The beginning of `ggml_cuda_mul_mat_vec_q`, before temporary Q8 allocation/conversion (M L1484; P L1436), is a demonstrated local prequantization seam with real F32 data, strides, stream and tensors available. Alternatively a mode dispatch can occur at `ggml_cuda_mul_mat` before MMVQ selection. This report does not freeze either choice or an API. The higher site preserves tensor roles more naturally but misses direct fused/MUL_MAT_ID calls unless explicitly covered; the lower site sees those calls but must correctly handle or reject fusion and IDs. Initially admitting ordinary Q1/F32/F32, a single column, full g128 groups, one selected device, documented strides, no IDs and no unsupported fusion is consistent with the contract. Reference fallback must remain explicit and countable. Audit all call sites again after the source pin and compatibility patchset are chosen.

## 5. Consuming-task requirements and unresolved evidence

**K05 proposals:** Build one independent byte decoder from the native scale/sign definition; test the exact bit positions 0,1,7,8,31,32,63,64,95,96,127, zero/fractional/negative scales, adjacent 18-byte groups and strided rows. Independently form B1/B2/B3 coefficients/residuals from original F32, decode `x_hat`, and compute ordinary FP32 scalar dots. Test integer mask dots exactly and scaled sums with documented tolerances. A separate Q8_1 reference-emulation fixture may compare CUDA numerics, but it must retain the per-32 scale and FP16 scale conversion rather than pretending there is one Q8 scale per g128. The host Q8_0 runtime route does not replace the independent F32 oracle. No tests were executed by this investigation.

**K08 proposals:** Freeze input/weight/destination type and shape eligibility, byte stride divisibility/bounds, device/stream ownership, scratch lifetime, reason-coded fallback and operation generation. Acquire basis scratch from the backend pool, prepare once per operation, reuse across output rows, and place the decision before Q8 conversion. Do not reuse an activation pointer as a cache key. Unsupported operation roles, views, multi-column prefill, IDs and fusion should have stated policy, not accidental behavior. Keep reference mode default and preserve FP32 graph outputs. Capture disablement or compatibility changes are K04/K08 decisions, not outcomes of this ABI research.

**Unknown:** Target CUDA 11/sm37 compilation, correctness of actual generated code, available K80 hardware, real model tensor types/shapes/roles, model-specific graph reachability, live operation counts, FP32 temporary-memory peaks, timing and numerical quality. These require K03–K08/K14 downstream evidence. This investigation establishes source semantics and specific candidate seams; it neither selects the source base nor declares any hardware acceptance complete.
