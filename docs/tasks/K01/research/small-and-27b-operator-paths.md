## Fused versus decomposed GDN: actual selectors, not an invented flag

Both have internal `llama_cparams.fused_gdn_ar`, `fused_gdn_ch`, `auto_fgdn` at [mainline llama-cparams.h:42-44](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-cparams.h#L42-L44), [Prism same lines](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-cparams.h#L42-L44). Whole-tree searches found no existing CLI or public context-param switch to force these false. Do not publish an imaginary `--no-fused-gdn` command.

Mainline initializes AR=true, CH=true, **auto_fgdn=false** at [llama-context.cpp:232-234](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-context.cpp#L232-L234). Its resolver code exists but the GDN auto-resolution block is not entered with these defaults: [505-565](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-context.cpp#L505-L565).

Prism initializes AR=true, CH=true, **auto_fgdn=true** at [308-310](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-context.cpp#L308-L310). `resolve_fused_ops` builds reserved probe graphs and disables a fused path when its assigned backend device differs from the layer device; this is the existing automatic route into decomposition: [608-668](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-context.cpp#L608-L668). It is a placement/capability check, not execution or numerical verification. A predicate falsely returning true defeats this protection. Both resolvers acknowledge the layer-device comparison is wrong for cases such as no KV offload.

`llm_build_delta_net_base::build_delta_net` selects on **tokens per sequence**, `q->ne[2]`, not on semantic prefill/decode. If exactly 1, fused AR or decomposed autoregressive; otherwise fused CH or chunking. A one-token prompt/prefill follows the AR shape branch too. Mainline [delta-net-base.cpp:425-447](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/delta-net-base.cpp#L425-L447); Prism [430-452](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/delta-net-base.cpp#L430-L452).

For an intentional diagnostic nonfused route, K04/K07 must make an explicit, recorded test-only internal change to these cparams, or add a reviewed local configuration surface through its owner. Merely setting `GGML_GDN_RAW_GATES_DISABLE` in Prism does **not** decompose GDN; it only moves sigmoid/softplus gate activation out of the fused kernel. The mainline default fused path itself is a valid first compile/run candidate: do not require decomposition absent an observed failure.

Decomposed one-token graph (same lines in both): q scaling; state multiplied by exp(g); state-key product/reduction; beta-weighted value correction; outer-product state update; state-query product/reduction. It uses elementwise arithmetic, sum_rows, transpose/view/repeat, not triangular solve. [Mainline:289-370](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/delta-net-base.cpp#L289-L370), [Prism:289-370](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/delta-net-base.cpp#L289-L370).

Decomposed multi-token graph is identical through line 398 in both candidates. Scalar GDN gates use chunk size 64 (vector-gated KDA would use 16), pad tokens, cumsum the transposed contiguous gates, form triangular decay/attention matrices, construct identity, call `ggml_solve_tri(lhs, attn, true, true, false)`, then chunked dense products and persistent state updates. [Mainline:61-89](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/delta-net-base.cpp#L61-L89), [125-183](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/delta-net-base.cpp#L125-L183), [235-283](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/delta-net-base.cpp#L235-L283); [Prism:61-283](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/delta-net-base.cpp#L61-L283). Hence “disable fusion” changes both graph shape and temporary/state traffic and does not remove CUDA compatibility work.

## cc 370 operator matrix and real fallback limits

| Path | Source behavior | cc 370 inference / required check |
|---|---|---|
| Fused GDN | F32 pointers/FP32 math, supported S_v cases 16/32/64/128; q/k/v contiguous rows, q/k same stride, gates/beta/state contiguous | No architecture-specific GDN rejection. Generic float shuffle-reduction route exists. Compile and run actual state/head dimensions; unsupported S_v aborts rather than automatically falling back. |
| GDN support predicate | Mainline true except MUSA; Prism also rejects `src[6]` row-indexed state | Kepler alone never triggers CPU/decomposition fallback. Must not equate “supports=true” with correct sm_37 code. |
| CUMSUM | CUDA dispatcher F32 only; innermost CS64 picks custom scan, even with CUB enabled (CUB block path requires >=1024) | Actual scalar-GDN chunked path does not depend on CUB execution; file/CUB build dependencies remain K04 concern. |
| TRI | Direct row mask/copy kernel | No tensor-core or BF16 requirement on F32 path. |
| SOLVE_TRI | Fast custom kernel only n<=64 and k<=32; otherwise cuBLAS StrsmBatched with DEFAULT_MATH, then restores TF32 mode | Chunk scalar GDN n=k=64 actually selects cuBLAS fallback, not custom fast path. Test status/numerics of math-mode calls on legacy toolchain/device. |
| SSM_CONV | CUDA support requires src0.ne[1] %128==0 | Match conv_channels from exact model header; do not infer unsupported or supported from model family alone. |

## Candidate-specific optional behavior and state

Prism fuses raw beta sigmoid and alpha softplus/scale into GDN when backend/parameter types allow it. `GGML_GDN_RAW_GATES_DISABLE` existing env presence restores activated gate inputs. GPU device registry CUDA is allowed; raw dt/a must be F32. [Prism qwen35.cpp:143-165](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/qwen35.cpp#L143-L165), [400-423](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/qwen35.cpp#L400-L423). Its rows-state path is CPU/Metal only; selected CUDA device forces the existing gathered state path, avoiding advertised CUDA rejection of src[6]: [434-453](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/qwen35.cpp#L434-L453). Prism GB10-only multi-column-per-warp/precomputed-exp optimizations are inapplicable at cc370. Prism also combines Q/K L2 normalization into one view [490-505](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/qwen35.cpp#L490-L505), unlike mainline's separate `build_gdn_l2_norm` calls. **This is also a numerical semantics difference**, not merely combined views: mainline places epsilon inside the square root, while Prism uses the max-norm formulation. See the [pinned formula comparison](candidate-comparison-and-import.md#correctness-difference-qwen35-gdn-normalization-is-not-merely-fused-launches). Preserve the selected mainline reference formula; K06 records actual epsilon and K07 checks small-norm/reference behavior if compatibility changes touch normalization.

With `n_rs_seq==0`, recurrent attention returns output and final state then explicitly copies state into cache. With snapshots enabled (`n_rs_seq>0`), it directly creates fused GDN with K=n_rs_seq+1 regardless of the normal decomposition selectors. Mainline [delta-net-base.cpp:527-605](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/delta-net-base.cpp#L527-L605), Prism [532-646](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/delta-net-base.cpp#L532-L646). Default n_rs_seq is 0 ([mainline context:3624](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-context.cpp#L3624)). Core text POC should retain that default unless deliberately testing supported rewind behavior. K08 must reset convolution state, recurrent state and full-attention KV plus prompt/prepared caches, preferably by context recreation for initial mode switches.

Optional MTP is separately loaded/skipped and separate `LLM_GRAPH_TYPE_DECODER_MTP`; normal pass only loops trunk `n_layer`. Mainline [qwen35.cpp:36-38](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/qwen35.cpp#L36-L38), [118-155](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/models/qwen35.cpp#L118-L155); Prism [40-42](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/qwen35.cpp#L40-L42), [122-184](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/models/qwen35.cpp#L122-L184). `load_mtp=false` defaults: [mainline llama-model.cpp:2778](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-model.cpp#L2778), [Prism:2944](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-model.cpp#L2944).
