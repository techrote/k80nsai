## 1. Hybrid clearing really includes recurrent memory

**S:** `llama_memory_hybrid::clear(bool data)` calls `mem_attn->clear(data)` and `mem_recr->clear(data)` at lines 138–140, identically in both candidates. It is wrong to claim that this hybrid clear clears only attention/KV. `seq_rm` at 143–149 invokes recurrent removal first and returns false before touching attention if recurrent removal refuses. [M hybrid clear/removal](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-memory-hybrid.cpp#L138-L150), [P hybrid clear/removal](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-memory-hybrid.cpp#L138-L150).

**S:** Attention `llama_kv_cache::clear` resets each stream's cells and head unconditionally; only `data=true` additionally zeroes its backend buffers. Recurrent `llama_memory_recurrent::clear` resets each cell's position, sequence set, source and tail; head and used count; and `rs_idx`. Its backend buffer zeroing is likewise conditional on `data`. Thus `false` means logical metadata clear without buffer zeroing, not attention-only clear. [M KV 369–380](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-kv-cache.cpp#L369-L380), [P KV 370–381](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-kv-cache.cpp#L370-L381), [M recurrent 141–159](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-memory-recurrent.cpp#L141-L159), [P recurrent 130–148](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-memory-recurrent.cpp#L130-L148).

**S:** Public `llama_memory_clear(mem,data)` is a null-safe direct call to `mem->clear(data)`; public `llama_memory_seq_rm` returns the implementation result, or true for null memory. They are memory APIs, not whole-application reset APIs. Public docs describe `[p0,p1)`, negative sequence wildcard, negative start/end bounds, and possible failure of partial removal. [M API declaration 737–752](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/include/llama.h#L737-L752), [P declaration 739–754](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/include/llama.h#L739-L754), [M wrappers 4022–4039](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-context.cpp#L4022-L4039), [P wrappers 4023–4040](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-context.cpp#L4023-L4040).

**S — source-level defect candidate:** Both recurrent implementations test `(uint32_t) seq_id >= n_seq_max` before their later negative-sequence branch. A negative wildcard such as `-1` therefore returns false for ordinary valid `n_seq_max`, despite the public wildcard contract; hybrid removal then leaves attention unmodified too. This is not a reproduced runtime failure, but follows directly from the inspected condition. Use `llama_memory_clear` for all-memory clear, or check concrete sequence removal results; do not equate `seq_rm(-1,-1,-1)` with hybrid clear. Concrete valid-sequence full removal normalizes bounds and resets recurrent snapshot index. Partial tail rollback is only accepted within `n_rs_seq` and with no pending rollback; other such partial requests return false. [M recurrent 161–216](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/src/llama-memory-recurrent.cpp#L161-L216), [P recurrent 150–205](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/src/llama-memory-recurrent.cpp#L150-L205).

**S:** `common_memory::seq_rm` calls a wrapper that aborts when public removal fails, rather than returning recoverable failure. [Both pins, common/common.cpp 1625–1652: M](https://github.com/ggml-org/llama.cpp/blob/56381e407c0ccfb3a6f71e668a27a901001d22ce/common/common.cpp#L1625-L1652), [P](https://github.com/PrismML-Eng/llama.cpp/blob/d8f26eec76da6d09bb708bcba51ef64b8cd868a3/common/common.cpp#L1625-L1652). ## 6. Concrete downstream handoff and targeted regressions

**K08 (shared owner; proposed, not implemented):** freeze context/backend-owned policy + evaluation generation + phase provenance; connect app phase to real dispatch or explicitly document single-column policy; invalidate graph/prepared state on reset/reload/policy changes; no activation-pointer-only cache. Source anchors are hybrid APIs and `process_ubatch`, not a nonexistent upstream K80 mode API.

**K13 (CLI owner):** prefer the existing in-process completion/common-helper route explicitly (simple-chat is the smaller alternative); central parser forwards native device controls; require exactly one selected device/split none/main index 0; reuse inspected template with fixed thinking setting. Implement `/help`, `/stats`, `/reset`, `/quit` and optional `/mode` through K08 only. Keep context across ordinary turns; on policy change announce fresh session, recreate sampler/context as needed, clear transcript/prefix/checkpoints and K08 caches; never load old-policy saved state. Handle EOG, error/abort, Unicode, context-full and Ctrl+C without silent history truncation or fake success exit. Core execution must not start listener/draft/vision paths.

**K17 proposed tests (no test has been run here):**

1. **Hybrid clear**: after both attention/recurrent activity, call `clear(false)` then fresh prompt; compare metadata/logits against a fresh context under identical policy; independently test `clear(true)` zeroing where inspectable. Check recurrent tail/src/rs_idx reset, not only a token count. Host fixture tests are separate from real hybrid-model K80 evidence.
2. **Removal contract**: full concrete sequence removal; partial recurrent tail removal outside snapshot capacity returns false without attention mutation; supported rollback boundaries; negative wildcard reproducer for the identified unsigned-cast condition. Do not paper over a false result with application counter reset.
3. **Policy switch**: run reference, switch to B1/scope/threshold then evaluate fixed token prefix; compare against a separately fresh B1 context with same seed/settings. Repeat B1 to reference. Deliberately same tensor addresses/graph shapes must not reuse old prepared bases/state. Invalid mode/threshold leaves current session unchanged.
4. **External caches/sampler**: seed a prefix cache/checkpoint/transcript and sampler history, reset, then resend same prefix. Assert no old state restored, sampler recreated deterministically, both memory families fresh. For any optional replay path compare to full fresh token replay, not free-running sequence positions.
5. **Phase**: one-token initial prompt, multi-token prefill ending with a one-token microbatch, cache-hit tail, normal one-token generation, and token-by-token transcript replay. A decode-only policy must leave every prompt/replay operation reference; single-column mode must label and count its prompt work.
